# دستورالعملِ فول‌استک — راهنمای استفاده

خودِ دستورالعمل: **[`FULLSTACK.md`](FULLSTACK.md)**

این پوشه یک بسته‌ی کامل است: قاعده‌ها + سازوکارِ به‌روز ماندنشان + سازوکارِ
هم‌گام‌کردنِ کدهایی که با نسخه‌ی قدیمی ساخته شده‌اند.

---

## دو راهِ استفاده

### راهِ ۱ — داخلِ مخزن (توصیه‌شده، بدونِ هیچ کاری از طرفِ تو)

همین حالا در این مخزن فعال است. `CLAUDE.md` خودش `FULLSTACK.md` را بار می‌کند و
هوکِ `.claude/hooks/guideline-boot.py` در شروعِ هر نشست نسخه و مهاجرتِ معلق را اعلام می‌کند.

**یعنی هیچ مقدمه‌ای لازم نیست.** بنویس «فرمِ ثبتِ خرج را اضافه کن» و دستورالعمل
خودش اعمال می‌شود.

### راهِ ۲ — آپلود در گفت‌وگو

`FULLSTACK.md` را در هر گفت‌وگویی (Claude Code، claude.ai، هرجا) آپلود کن. بخشِ §۰
همان فایل خطاب به دستیار نوشته شده و خودش را فعال می‌کند. جوابی که باید بگیری
دقیقاً یک خط است:

> دستورالعملِ فول‌استک v2026.08.1 فعال شد.

بعدش عادی کار کن. لازم نیست بنویسی «طبقِ دستورالعمل…».

## نصب روی یک پروژه‌ی دیگر

```bash
# ۱) خودِ بسته
cp -r guidelines/ /مسیرِ/پروژه‌ی‌جدید/

# ۲) هوک و دستورها
#    ⚠️ اگر پروژه‌ی مقصد از قبل .claude/settings.json دارد، رونویسی‌اش نکن —
#       فقط بلوکِ SessionStart را داخلش ادغام کن.
cp -r .claude/commands .claude/hooks /مسیرِ/پروژه‌ی‌جدید/.claude/

# ۳) در پروژه‌ی جدید، lock.json را برای همان پروژه تنظیم کن
#    - verify  → فرمانِ واقعیِ تست/لینتِ همان پروژه
#    - areas   → پوشه‌های همان پروژه
#    - waivers → خالی شروع کن

# ۴) ⚠️ مهم‌ترین گام: در source.json مقدارِ is_origin را false کن
#    اگر true بماند، gl-update فکر می‌کند اینجا خودِ منبع است و
#    هیچ‌وقت به‌روزرسانی نمی‌گیرد.

# ۵) و برای پروژه‌ای که ماه‌ها بازش نمی‌کنی:
cp guidelines/templates/guideline-upstream.yml .github/workflows/
echo 'guidelines/.upstream-cache.json' >> .gitignore
```

`self-check.py` پارسرِ مهاجرت را از `.claude/hooks/guideline-boot.py` برمی‌دارد،
پس هر دو را کپی کن — وگرنه یکی از بررسی‌ها قرمز می‌شود.

بعد در Claude Code:

```
/gl-check      # ببین کدِ فعلی کجاها با دستورالعمل نمی‌خواند
/gl-migrate    # مُهرِ اولیه را بزن
```

اگر پروژه `CLAUDE.md` ندارد، یکی بساز با همان ساختارِ ریشه‌ی این مخزن —
مهم‌ترین بخشش **ترتیبِ اولویت** است، تا دستورالعملِ عمومی روی قاعده‌های آن پروژه سوار نشود.

## چرخه‌ی به‌روزرسانی

```
        هفتگی (خودکار)                      دستی، هر وقت خواستی
   ┌──────────────────────┐              ┌──────────────────────┐
   │ guideline-drift.yml  │              │      /gl-sync full   │
   └──────────┬───────────┘              └──────────┬───────────┘
              │                                     │
      عقب‌افتادگیِ کوچک ──→ PRِ خودکار                │
      پرشِ نسخه‌ی اصلی ──→ ایشو ────────────────────→ بازنگریِ محتوایی
                                                     │
                                          نسخه‌ی تازه + CHANGELOG
                                          + ورودیِ MIGRATIONS (اگر لازم)
                                                     │
                                                     ▼
                                    هوکِ شروعِ نشست می‌گوید «N مهاجرت معلق»
                                                     │
                                                     ▼
                                              /gl-migrate
                                    گام‌به‌گام · وارسی بعد از هر گام · کامیتِ جدا
                                                     │
                                                     ▼
                                        lock.json جلو می‌رود — و فقط آن‌وقت
```

نکته‌ی اصلی: **`lock.json` مالِ کد است، نه مالِ دستورالعمل.** نه `/gl-sync` و نه
`/gl-pull` جلویش نمی‌برند (MIG-07). تا وقتی `/gl-migrate` اجرا نشده، فاصله باقی
می‌ماند و هر نشست یادآوری می‌شود. این تنها چیزی است که نمی‌گذارد کدهای قدیمی
بی‌صدا جا بمانند.

## وقتی این بسته در چند پروژه است

یک مخزن **منبع** است و بقیه فقط از آن می‌خوانند (SELF-05). سه لایه نمی‌گذارند
کپی‌ها کهنه بمانند:

| کِی | چه چیزی |
|---|---|
| هر بار پروژه را باز کنی | هوکِ شروعِ نشست می‌گوید «منبع روی X است، تو روی Y» |
| هر وقت خودت بخواهی | `/gl-pull` یا `python3 guidelines/gl-update.py --apply` |
| هفتگی، حتی اگر پروژه را باز نکنی | گردش‌کارِ `guideline-upstream.yml` که PR باز می‌کند |

**هوک هیچ‌وقت منتظرِ شبکه نمی‌ماند.** کشِ روی دیسک را می‌خواند و اگر کهنه بود
(بیش از ۱۲ ساعت) یک فرآیندِ جدا در پس‌زمینه تازه‌اش می‌کند. اندازه‌گیری شد: ۵۰ تا
۹۰ میلی‌ثانیه، حتی وقتی شبکه قطع است. هوکی که به اینترنت بند باشد، آفلاین یا پشتِ
VPNِ کند شروعِ کار را می‌خواباند — و آن بدتر از ندانستنِ نسخه است.

### سه محافظِ `gl-update.py`

- **`lock.json` هیچ‌وقت از منبع نمی‌آید.** مُهرِ همین پروژه است.
- **فایلی که محلی عوض شده بی‌صدا رونویسی نمی‌شود** — `--force` می‌خواهد. (هشِ آخرین
  همگام‌سازی در `.upstream.json` نگه داشته می‌شود تا «عقب» از «دست‌کاری‌شده» تشخیص داده شود.)
- **کدِ اجرایی جز با `--with-tools` نمی‌آید.** سندها خودکار، اسکریپت و هوک با
  تصمیمِ آدم — یا از راهِ PR که دیده می‌شود.

### جهت یک‌طرفه است

اگر در یک پروژه قاعده‌ای بهتر شد، **همان‌جا به `FULLSTACK.md` اضافه‌اش نکن**. در
مخزنِ منبع با `/gl-sync` واردش کن تا به همه برسد. فایلی که محلی ویرایش شده، از آن
به بعد به‌روزرسانی نمی‌گیرد و بی‌صدا جا می‌مانَد.

## پرسش‌های محتمل

**دستورالعمل با قاعده‌ی پروژه‌ام جنگید، چه می‌شود؟**
قاعده‌ی پروژه برنده است (§۱). اگر انحراف عمدی است، در `lock.json` → `waivers`
ثبتش کن تا دیگر پیشنهادِ تکراری نگیری.

**همه‌ی کدهای قدیمی‌ام باید مهاجرت کنند؟**
نه. فقط قاعده‌های مربوط به **درستی، امنیت، داده و دسترس‌پذیری** اجباری‌اند.
تغییرِ سبک و انتخابِ فناوری بدونِ درخواستِ صریحِ تو انجام نمی‌شود (MIG-04).

**نمی‌خواهم هوک اجرا شود.**
`.claude/settings.json` را حذف کن. `CLAUDE.md` همچنان دستورالعمل را بار می‌کند؛
فقط اعلامِ خودکارِ مهاجرت را از دست می‌دهی.

**PRِ خودکار باز نمی‌شود.**
`Settings → Actions → General → Allow GitHub Actions to create and approve pull requests`
باید روشن باشد. شاخه در هر حال push می‌شود، پس دستی هم می‌شود PR زد.

**اگر شبکه نبود؟**
`check-drift.py` با کدِ ۳ برمی‌گردد و گردش‌کار فقط هشدار می‌دهد. `self-check.py`
اصلاً به شبکه نیاز ندارد.
