# mlqvoice — گفتار به متن برای ویندوز، مخصوصِ برنامه‌نویس‌ها

ابزارِ مستقل. **به پنل و به دیتابیسِ Supabase هیچ ربطی ندارد** و روی سرور نمی‌رود.

کلیدِ میان‌بُر را می‌زنی، یک کادر وسطِ صفحه می‌آید، حرف می‌زنی، متن همان‌جا نوشته
می‌شود، ویرایشش می‌کنی، و با یک دکمه در همان پنجره‌ای که قبلش تویش بودی نوشته می‌شود.
دوباره زدنِ همان کلید ضبط را متوقف می‌کند.

---

## ۱. راه‌اندازی

**آماده‌ترین راه — exeِ ساخته‌شده.** گردش‌کارِ `voice-windows.yml` روی یک ماشینِ
واقعیِ ویندوز می‌سازدش و قبل از انتشار خودش را چهار بار اجرا می‌کند. از صفحه‌ی
Actions مخزن، آخرین اجرای سبز → بخشِ **Artifacts** → `mlqvoice-exe`.

برای اینکه با ویندوز بالا بیاید، یک میان‌بُر از exe را در `shell:startup` بگذار.

**ساختِ محلی:**
```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

**اجرا از سورس** — اگر چیزی خراب بود این را اول امتحان کن: exe با `--windowed`
ساخته می‌شود و کنسول ندارد، ولی این‌طور خطاها جلوی چشمت‌اند:
```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m mlqvoice check     # اول این
python -m mlqvoice           # خودِ برنامه
```

**لازم است:** ویندوز، اینترنت، و کروم یا اِج (دلیلش بخشِ ۳).

## ۲. کار کردن با آن

| کار | چطور |
|-----|------|
| شروع/توقفِ ضبط | `Ctrl+Alt+Space` (قابلِ تغییر) |
| نوشتن در پنجره‌ی مقصد | دکمه‌ی **بنویس** یا `Ctrl+Enter` |
| بستنِ کادر | `Esc` یا دکمه‌ی **بستن** |
| جابه‌جا کردنِ کادر | با ماوس بکشش |
| تنظیمات و دیکشنری | راست‌کلیک روی آیکنِ کنارِ ساعت |

«پنجره‌ی مقصد» همان پنجره‌ای است که **درست قبل از زدنِ کلیدِ میان‌بُر** تویش بودی؛
اسمش بالای کادر نوشته می‌شود تا قبل از زدنِ «بنویس» ببینی متن کجا می‌رود.

## ۳. تشخیصِ گفتار — و چرا کروم لازم است

خواسته این بود که از موتورِ فارسیِ گوگل استفاده شود، همان که پشتِ دکمه‌ی میکروفونِ
گوگل ترنسلیت است. راهِ رسیدن به آن بدونِ کلیدِ پولیِ Cloud، فقط **Web Speech API** است
و آن هم فقط داخلِ کروم زندگی می‌کند. پس برنامه یک صفحه‌ی تک‌فایل را روی
`127.0.0.1` سرو می‌کند و آن را در کرومِ خودِ تو باز می‌کند — در یک **پروفایلِ جدا**
(به پروفایلِ شخصی‌ات دست نمی‌زند) و پنجره‌ای که بیرونِ دیدِ صفحه گذاشته می‌شود.

نتیجه‌ی تشخیص از همان‌جا روی loopback به برنامه برمی‌گردد. هر درخواست یک **توکنِ
تصادفی** دارد که موقعِ اجرا ساخته می‌شود؛ بدونِ آن هر برنامه‌ی دیگری روی همان کامپیوتر
می‌توانست متن به `/result` بفرستد و این برنامه هرچه بگیرد را در صفحه‌کلیدِ تو تایپ
می‌کند. (تستش در `tests/test_bridge.py` هست.)

**اندازه‌گیری‌شده:** اندپوینتِ غلط‌گیرِ گوگل ترنسلیت (`dt=sp`) برای فارسی **هیچی
برنمی‌گرداند** — سه ورودیِ غلط را عیناً پس داد. برای همین لایه‌ی دیکشنری کاملاً
محلی است: هم سریع‌تر، هم متنِ کدی که دیکته می‌کنی جایی فرستاده نمی‌شود.

## ۴. دیکشنری — قلبِ ماجرا

خروجیِ خامِ گوگل برای یک برنامه‌نویسِ فارسی‌زبان قابلِ استفاده نیست: «کامیت» را
فارسی می‌نویسد، «نقطه» را کلمه‌ی «نقطه» می‌نویسد نه `.`، و املا را بینِ `ی` فارسی و
`ي` عربی قاطی می‌کند. سه مرحله روی متن اجرا می‌شود:

**۱. یکسان‌سازیِ املا** — `ك`→`ک`، `ي`→`ی`، حذفِ اعراب، ارقام به لاتین (پیش‌فرض، چون
برای کد است)، و چسباندنِ نیم‌فاصله (`می روم` → `می‌روم`).

**۲. واژه‌نامه‌ی برنامه‌نویسی** — ۲۳۴ مدخل: `کامیت`→`commit`، `دیتابیس`→`database`،
`ری اکت`→`React`.

> **دامی که با دقت دور زده شده:** کلمه‌ای که در فارسیِ روزمره معنیِ دیگری دارد
> **تک‌کلمه‌ای وارد واژه‌نامه نشده**. «پول» یعنی money نه `pull`، «نود» یعنی ۹۰ نه
> `Node`، «راست» یعنی right نه `Rust`. این‌ها فقط در ترکیبِ چندکلمه‌ای می‌آیند
> (`پول ریکوئست` → `pull request`). یک تستِ خودکار جلوی برگشتنشان را می‌گیرد.

**۳. نشانه‌های گفتاری** — `نقطه`→`.`، `پرانتز باز`→`(`، `آندرلاین`→`_`،
`خط جدید`→ سطرِ تازه، `مساوی`→`=`. هر نشانه خودش می‌داند به کدام طرف می‌چسبد، پس
`تابع پرانتز باز ایکس پرانتز بسته` می‌شود `تابع (ایکس)` نه `تابع ( ایکس )`.

### واژه‌ی خودت را اضافه کن

راست‌کلیک روی آیکن → **دیکشنریِ من**. فایلِ `dictionary.json` در
`%APPDATA%\mlqvoice\` باز می‌شود:

```json
{
  "terms": {
    "kubectl": ["کیوب سی تی ال"],
    "Supabase": ["سوپابیس", "سوپا بیس"]
  },
  "symbols": [
    { "say": ["تیلدا"], "text": "~", "attach": "both" }
  ]
}
```

کلید همان چیزی است که **نوشته** می‌شود؛ فهرستِ روبه‌رویش شکل‌هایی است که ممکن است
**بگویی**. مدخلِ تو روی مدخلِ داخلیِ هم‌نام می‌نشیند، پس اگر «کامیت» را فارسی
می‌خواهی، `"کامیت": ["کامیت"]` بگذار.

`attach` می‌گوید نشانه چطور فاصله بگیرد: `left` (چسبیده به کلمه‌ی قبل، مثلِ `.`)،
`right` (چسبیده به بعدی، مثلِ `(`)، `both` (هیچ فاصله‌ای، مثلِ `_`)، `none`
(فاصله از دو طرف، مثلِ `=`).

**بدونِ حرف زدن امتحانش کن** — سریع‌ترین راهِ تستِ یک واژه‌ی تازه:
```
python -m mlqvoice say کیوب سی تی ال رو بزن
```

## ۵. تنظیمات

`%APPDATA%\mlqvoice\config.json` (راست‌کلیک روی آیکن → تنظیمات):

| کلید | پیش‌فرض | کار |
|------|---------|-----|
| `hotkey` | `ctrl+alt+space` | ترکیبِ کلید. کلیدِ تنها فقط `f1`..`f24` مجاز است |
| `lang` | `fa-IR` | زبانِ تشخیص |
| `digits` | `latin` | `latin` / `fa` / `keep` |
| `zwnj` | `true` | چسباندنِ نیم‌فاصله |
| `glossary` | `true` | واژه‌نامه‌ی برنامه‌نویسی |
| `punctuation` | `true` | نشانه‌های گفتاری |
| `interim` | `true` | نمایشِ حدسِ زنده زیرِ کادر |
| `insert_mode` | `paste` | `paste` (سریع) یا `type` (کاراکتربه‌کاراکتر) |
| `restore_clipboard` | `true` | برگرداندنِ کلیپ‌بورد بعد از paste |
| `close_after_insert` | `true` | خالی‌کردنِ کادر بعد از نوشتن |
| `browser_path` | `""` | مسیرِ دستیِ کروم، اگر خودکار پیدا نکرد |
| `port` | `0` | `0` یعنی سیستم انتخاب کند |

`python -m mlqvoice check` تنظیمات را می‌سنجد و می‌گوید چه می‌فهمد.

اگر جایی paste کار نکرد (بعضی ترمینال‌ها `Ctrl+V` را نمی‌پذیرند)، `insert_mode` را
روی `type` بگذار.

## ۷. تصمیم‌هایی که عمدی‌اند — عوضشان نکن بدونِ دلیل

- **حدسِ زنده (interim) هیچ‌وقت داخلِ کادرِ ویرایش نمی‌رود**، زیرش در یک خطِ جدا
  نشان داده می‌شود. Web Speech متنِ interim را مدام بازنویسی می‌کند؛ اگر داخلِ کادر
  می‌رفت، سرِ مکان‌نما با کاربر دعوا می‌کرد و ویرایشش را بی‌صدا خنثی می‌کرد — و
  ویرایش‌پذیر بودنِ کادر کلِ دلیلِ وجودش است. تستِ خودکار دارد.
- **پنجره‌ی مقصد در لحظه‌ی زدنِ کلید ذخیره می‌شود، نه در لحظه‌ی زدنِ «بنویس»** —
  چون آن موقع پنجره‌ی فعال خودِ کادرِ ماست.
- **`focus_window` نتیجه برمی‌گرداند و `insert` روی `False` تایپ نمی‌کند.** اگر
  فوکوس منتقل نشده باشد و باز هم تایپ کنیم، متن می‌پاشد داخلِ هر چیزی که فعال است —
  در بدترین حالت ترمینالی که آماده‌ی اجرا است.
- **ساختارهای Win32 با تایپ‌های عرضِ‌ثابت نوشته شده‌اند، نه `wintypes`.**
  `wintypes.DWORD` همان `c_ulong` است که روی ویندوز ۴ بایت و روی لینوکسِ ۶۴ بیتی
  **۸ بایت** است — یعنی چیدمانِ ساختار به سکوی import وابسته می‌شد و `SendInput`
  کلِ دسته را رد می‌کند اگر `cbSize` نخواند. حالا `sizeof(INPUT)` روی هر سکو ۴۰
  است و تستش هم همین را می‌سنجد.
- **دکمه‌ی «بنویس» وقتی کادر خالی است غیرفعال است** و خطا هیچ‌وقت بی‌صدا بلعیده
  نمی‌شود؛ دکمه‌ای که به‌ظاهر هیچ کاری نمی‌کند بدترین حالت است، چون کاربر متن را
  گفته و نمی‌داند گم شد یا نه.

## ۸. چه چیزی وارسی شده و چه چیزی نه — صادقانه

**روی ویندوزِ واقعی اجرا شده** (گردش‌کارِ `voice-windows.yml`، `windows-latest`):
کلِ مجموعه‌ی تست، ساختِ exe، و بالا آمدنِ خودِ exe — نسخه‌اش را چاپ کرد. یعنی
این‌ها دیگر استدلال نیستند: چیدمانِ ساختارهای `SendInput` (`sizeof(INPUT) == 40`)
روی خودِ ویندوز درست است، و بسته اجرا می‌شود.

گردش‌کار بعد از ساخت، exe را با `check` و `say` و `selftest` هم می‌زند تا معلوم
شود PySide6 و پلاگینِ سکویش و فایل‌های دیکشنری واقعاً داخلِ بسته رفته‌اند. اگر
این خط را می‌خوانی و آخرین اجرای گردش‌کار سبز است، هر سه پاس شده‌اند.

**سه باگ را همین اجراها پیدا کردند، نه استدلال:**

| باگ | چرا روی لینوکس نامرئی بود |
|-----|---------------------------|
| هر `print` فارسی با `UnicodeEncodeError` می‌افتاد | لینوکس UTF-8 است؛ ویندوز کدپیجِ ANSI را برمی‌دارد |
| exe با «attempted relative import» می‌مرد | فقط بسته‌ی PyInstaller این مسیر را می‌رود |
| exeِ بدونِ کنسول `sys.stdout is None` دارد | فقط در بسته‌ی `--windowed` پیش می‌آید |

**ولی این‌ها هنوز اجرا نشده‌اند و ادعایی درباره‌شان نمی‌کنم** — همه‌شان به یک
کاربرِ زنده و یک میکروفون نیاز دارند و CI هیچ‌کدام را ندارد:

1. `RegisterHotKey` و حلقه‌ی پیام — کد نوشته شده، کلید فشرده نشده.
2. `SendInput` و paste در پنجره‌ی مقصد، و `AttachThreadInput` برای برگرداندنِ فوکوس.
3. باز شدنِ کروم با پروفایلِ جدا و گرفتنِ خودکارِ اجازه‌ی میکروفون.
4. خودِ تشخیصِ گفتارِ فارسی — هیچ صدایی از این محیط عبور نکرده.
5. اینکه کروم در پنجره‌ی بیرونِ دید تشخیص را ادامه می‌دهد یا نه. پرچم‌های ضدِ
   throttling گذاشته شده‌اند، ولی **سنجیده نشده**.

**درسِ روشی از همین دور:** دو بار شکستی که *شبیهِ* باگِ برنامه بود، باگِ خودِ
سنجه بود — یک بار هارنسِ تست با locale والد رمزگشایی می‌کرد، یک بار PowerShell
منتظرِ یک بسته‌ی GUI نمی‌مانْد و کدِ خروجیِ خالی را «شکست» می‌خواند. هر دو وقتی
پیدا شدند که لاگ خوانده شد، نه وقتی حدس زده شد.

اولین بار که روی ویندوز اجرایش کردی، اگر جایی خطا داد بگو. هر باگی که پیدا شد
اول یک تستِ خودکار می‌گیرد که قبل از اصلاح قرمز باشد.
