# رباتِ تلگرام — نسخه‌ی مرجع

`index.ts` یک **کپیِ مرجع** از Supabase Edge Function به نامِ `telegram-bot` است
(پروژه‌ی `jdvbvuikbkebwxfsepft`). روی سرور نمی‌رود و در `modland-panel.zip` هم نیست؛
فقط برای این‌جاست که کدِ ربات از دست نرود و تغییرهایش در تاریخچه‌ی گیت دیده شود.

**منبعِ حقیقت نسخه‌ی مستقر است، نه این فایل.**

## آخرین وضعیت

- نسخه‌ی مستقر: **۳۲**
- `sha256` برابرِ همین فایل: `442b590a5e9251105757e55155116482073707b46767eb417e2dbcc74d791aca`
- `verify_jwt`: خاموش (خودِ تابع با `?secret=BOT_TOKEN` احراز می‌کند)

## روالِ درستِ ویرایش

بازتایپِ فایل از داخلِ چت ممنوع — ۳۹۸۹ نویسه‌ی غیرِانگلیسی و ۵۸ نیم‌فاصله‌ی نامرئی دارد
و یک نویسه‌ی جابه‌جا شده رباتِ زنده را می‌خواباند. به‌جایش:

1. `get_edge_function` بزن و متنِ مستقر را بگیر.
2. `sha256` آن را با همین فایل مقابله کن. اگر فرق داشت، **اول بفهم چرا** — یعنی
   کسی بیرون از گیت دستکاری کرده و کپیِ محلی کهنه است.
3. ویرایش را **برنامه‌ای** انجام بده (`str.replace` با `assert count == 1`)، نه دستی.
4. `tsc --noEmit --noResolve` بزن و خطاها را با خطاهای فایلِ قبلی مقایسه کن؛ باید
   همان‌ها باشند و نه بیشتر.
5. مستقر کن، بعد **دوباره** `get_edge_function` بگیر و `sha256` را مقابله کن.
6. سه مسیرِ عمومی را دود‌تست کن — هر سه باید بدونِ توکن جواب بدهند:

```
?cron=weekly      → 401 no      (کلید ندارد)
?media=<uuidِ الکی> → 404 none    (یعنی به دیتابیس رسید)
?secret=wrong     → 401 no
```

7. همین فایل و شماره‌ی نسخه‌ی بالا را به‌روز کن و commit بزن.

## نکته‌های امنیتی

- `/claimadmin` **عمداً حذف شده** (نسخه‌ی ۳۲). اگر روزی `bot_admins` خالی می‌شد،
  هر غریبه‌ای با فرستادنِ آن دستور مدیرِ فروشگاه می‌شد. افزودنِ مدیر حالا فقط با
  `insert` مستقیم در دیتابیس است. **برش نگردان.**
- کلیدِ cron داخلِ کد نیست: `cronKey()` اول `CRON_KEY` را از Secrets می‌خواند و
  اگر نبود از جدولِ `app_config` (کلیدِ `cron_key`). اگر عوضش کردی، هم `app_config`
  هم `cron.job` را با هم عوض کن.
- `BOT_TOKEN` و `SUPABASE_SERVICE_ROLE_KEY` فقط از `Deno.env` خوانده می‌شوند.
