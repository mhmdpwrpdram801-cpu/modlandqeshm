# بازرسِ عمومیِ اپلیکیشن‌های وب

یک موتور برای همه‌ی پروژه‌ها. کدِ پروژه را دست نمی‌زند؛ فقط می‌خواند و اجرا می‌کند.

## اجرا

    python3 audit.py مسیرِ/index.html                    # بدونِ تنظیمات
    python3 audit.py مسیرِ/index.html -c config.json     # با تنظیماتِ پروژه

اگر فایلی به نامِ `audit.config.json` کنارِ خودِ پروژه باشد، خودکار برداشته می‌شود.
کدِ خروجی: ۰ یعنی آماده‌ی تحویل، ۱ یعنی ایراد دارد.

### کلیدهای خطِ فرمان

| کلید | کار |
|---|---|
| `--json out.json` | گزارشِ ماشین‌خوان برای CI (همه‌ی نتایج، سطح، زمان‌بندی، رگرسیون) |
| `--only a11y,forms` | فقط این بخش‌ها اجرا شود |
| `--skip shots,visual` | این بخش‌ها اجرا نشود (بر `--only` هم اثر می‌گذارد) |
| `--deep` | بررسی‌های سنگین هم اجرا شود (الان: پوششِ کد) |
| `--state DIR` | پوشه‌ی وضعیت؛ پیش‌فرض `.audit` کنارِ خودِ پروژه |
| `--no-save` | وضعیتِ این اجرا ذخیره نشود (مرجعِ اجرای بعدی عوض نشود) |
| `--list` | فهرستِ نامِ بخش‌ها |
| `--quiet` | فقط خلاصه، بدونِ سطرِ سبزِ هر بررسی |

پیش‌نیاز: `playwright` (کرومیوم) و `node` (برای `node --check`) و `Pillow` (برای مقایسه‌ی تصویری).
**هیچ‌کدام اجباری نیستند** — اگر نباشند، بازرس یک پیامِ روشن می‌دهد و بقیه‌ی بررسی‌ها را ادامه می‌دهد.
اگر کرومیومِ همراهِ playwright نصب نیست ولی مرورگر جای دیگری داری:
`AUDIT_CHROMIUM=/path/to/chrome python3 audit.py ...`

## چه چیزهایی را می‌گیرد (بدونِ هیچ تنظیماتی)

**ایستا — بدونِ مرورگر**

| بخش | می‌گیرد |
|---|---|
| `syntax` | سینتکسِ هر اسکریپت (`node --check`) |
| `ids` | شناسه‌ی تکراری در صفحه |
| `dom` | عنصری که کد صدا می‌زند ولی وجود ندارد (شناسه‌ی پویا مثلِ `'q'+i` را حساب نمی‌کند) |
| `handlers` | دکمه‌ای که تابعِ ناموجود صدا می‌زند |
| `ghost` | نامِ تابعِ حذف‌شده که به‌صورت متن پاس داده می‌شود (باگِ خاموش) |
| `debug` | کدِ اشکال‌زداییِ جامانده (`console.log` / `debugger` / TODO) — هشدار |
| `forbidden` | ردِ چیزهایی که باید حذف می‌شدند (از تنظیمات) |
| `schema` | پرس‌وجویی که ستون یا جدولِ ناموجود صدا می‌زند |
| `bundle` | کتابخانه‌ی سنگینِ درون‌خطی که در شروع بار می‌شود — هشدار |
| `sw` | فایلی که در فهرستِ کشِ Service Worker هست ولی وجود ندارد (نصبِ SW را می‌شکند) |
| `sql` | بررسی‌های یکپارچگیِ داده (بخشِ بعد) |

**زنده — در مرورگرِ واقعی، صفحه‌ی ۴۱۲ پیکسلی**

| بخش | می‌گیرد |
|---|---|
| `boot` | خطای هنگامِ بالا آمدن |
| `screens` | خطا در هر صفحه |
| `csp` | نقضِ قفلِ امنیتی (CSP) |
| `network` | درخواستِ شبکه‌ی ناموفق |
| `values` | نشتِ `NaN` / `undefined` / `Infinity` در متنِ صفحه — حتی در بخش‌های مخفی |
| `touch` | دکمه‌ای که زیرِ چیزِ دیگری گیر کرده و لمس نمی‌شود (`elementFromPoint`، نه صدا زدنِ تابع) |
| `overlay` | پنجره‌ی شفاف که پشتش دیده می‌شود |
| `narrow` | بیرون‌زدگی در صفحه‌ی باریک (۳۲۰ پیکسل) — هشدار |
| `themes` | باز شدنِ همه‌ی صفحه‌ها در تمِ تاریک و روشن |
| `checks` | ادعاهای خودِ پروژه درباره‌ی پول و منطق (از تنظیمات) |
| `a11y` | هدفِ لمسِ کوچک‌تر از ۴۴×۴۴، ورودیِ بی‌برچسب، `<img>` بدونِ `alt`، فرارِ فوکوس از پنجره — همه هشدار |
| `perf` | حجمِ صفحه در شروع، بزرگ‌ترین منابع، FCP، تعاملی‌شدنِ DOM، پایانِ بارگذاری |
| `coverage`\* | کتابخانه‌ای که بار می‌شود ولی هرگز اجرا نمی‌شود (پوششِ بایت‌به‌بایتِ V8) |
| `shots` | عکس‌برداری در `/tmp/audit_shots` — **حتماً چندتا را با چشم ببین** |
| `visual` | مقایسه‌ی عکس‌ها با اجرای قبلی |
| `forms` | پر کردنِ هر ورودی با مقادیرِ مرزی (خالی، خیلی بلند، منفی، `<script>`، فارسی/RTL) |

\* فقط با `--deep`.

## مقایسه با اجرای قبلی (رگرسیون)

نتیجه‌ی هر اجرا در `.audit/last.json` (کنارِ خودِ پروژه) ذخیره می‌شود و اجرای بعدی می‌گوید:

```
━━━ مقایسه با اجرای قبلی ━━━
  🔻 تازه خراب شد: مقدارِ خراب: فاکتور → NaN
  🔺 درست شد: عنصرِ گمشده: tFinal
```

یعنی وقتی جایی را درست می‌کنی، معلوم می‌شود جای دیگری را شکسته‌ای یا نه.
مقایسه فقط روی بخش‌هایی انجام می‌شود که در **هر دو** اجرا اجرا شده‌اند، پس
`--only` گزارشِ الکیِ «درست شد» نمی‌سازد. همین فهرست در `--json` هم زیرِ `regression` می‌آید.

## مقایسه‌ی تصویری

عکس‌های هر اجرا در `.audit/shots` نگه داشته می‌شوند و اجرای بعدی پیکسل‌به‌پیکسل مقایسه می‌کند.
اگر صفحه‌ای بیش از `visual_threshold` درصد (پیش‌فرض ۲٪) فرق کرد، **هشدار** می‌دهد — نه ایراد،
چون تغییرِ ظاهری معمولاً عمدی است.

نواحیِ پویا (ساعت، تاریخ، عددِ زنده) را در `visual_ignore` بنویس تا ماسک شوند؛
وگرنه هر اجرا هشدارِ کاذب می‌گیری:

```json
"visual_ignore": ["#clock", ".live-total"]
```

## تنظیماتِ پروژه (همه اختیاری)

```json
{
  "name": "اسمِ پروژه",
  "fixture": "fixture.js",        // شبیه‌سازِ شبکه، تا تست به سرورِ واقعی نزند
  "schema": "schema.txt",         // سطرهای «جدول|ستون۱,ستون۲» برای مقابله‌ی پرس‌وجوها
  "assets": ["sw.js", "app.css"], // فایل‌های جانبی که باید کنارِ صفحه سرو شوند
  "login": [
    {"fill": "#email", "value": "a@b.c"},
    {"fill": "#pass",  "value": "x"},
    {"click": "#btn", "wait": 1100, "timeout": 5000}
  ],
  "reset": "document.querySelectorAll('.overlay').forEach(o=>o.classList.add('hidden'))",
  "screens": [["داشبورد", "nav('dashboard')"], ["فاکتور", "openInvoice('1')"]],
  "forbidden": ["stock", "cost_price"],   // چیزهایی که حذف شده‌اند و نباید ردی بمانَد
  "themes": [{"name": "تاریک", "js": "document.documentElement.setAttribute('data-theme','dark')"}],
  "narrow_width": 320,
  "allow_missing_ids": ["idهایی که عمداً پویا ساخته می‌شوند"],
  "skip": ["visual"],             // بخش‌هایی که این پروژه لازم ندارد
  "deep": false,                  // بررسی‌های سنگین

  "touch_min": 44,                // کوچک‌ترین هدفِ لمسِ قابلِ قبول
  "heavy_inline_kb": 120,         // از این بزرگ‌تر: «کتابخانه‌ی سنگینِ شروع»
  "visual_threshold": 2.0,        // درصدِ تغییرِ تصویری که هشدار می‌گیرد
  "visual_ignore": ["#clock"],    // ناحیه‌های پویا در مقایسه‌ی تصویری
  "sw": "sw.js",                  // اگر خودکار پیدا نشد
  "form_values": ["", "-1"],      // مقادیرِ مرزیِ دلخواه برای فرم‌ها
  "forms_submit": false,          // فرم‌ها ثبت هم بشوند؟ (فقط با fixture معنی دارد)

  "perf_budget": {"weight_kb": 1500, "fcp_ms": 2500, "dom_interactive_ms": 3000},

  "db_env": "DATABASE_URL",
  "sql_checks": [
    {"name": "مبلغِ منفی در پرداخت‌ها نیست",
     "sql": "select count(*) from payments where amount < 0", "expect": 0}
  ],

  "checks": [
    {"name": "جمعِ فاکتور",
     "before": "openInvoice('1')", "wait": 600,
     "js": "()=>document.getElementById('total').textContent",
     "expect": "۲٬۵۰۰٬۰۰۰"}
  ]
}
```

`checks` مهم‌ترین بخشِ اختصاصیِ هر پروژه است: هر ادعایی درباره‌ی **پول یا منطق** را
اینجا بنویس تا هر بار خودکار سنجیده شود.

### یکپارچگیِ داده (`sql_checks`)

اگر متغیرِ محیطیِ `db_env` تنظیم باشد و `psycopg` نصب باشد، کوئری‌ها واقعاً اجرا می‌شوند و
نتیجه با `expect` مقابله می‌شود. وگرنه بازرس **قرمز نمی‌دهد** — فقط هشدار می‌دهد و
دستورِ آماده را چاپ می‌کند تا خودت اجرا کنی:

```
⚠️  بررسی‌های SQL اجرا نشد (متغیرِ DATABASE_URL تنظیم نشده) — دستورها را دستی اجرا کن:
     · psql "$DATABASE_URL" -c "select count(*) from payments where amount < 0"
     ·    انتظار: 0  ← مبلغِ منفی در پرداخت‌ها نیست
```

## در CI

```bash
python3 audit.py dist/index.html -c audit.config.json --json report.json || exit 1
```

`report.json`:

```json
{ "counts": {"pass": 41, "warn": 3, "fail": 0},
  "results": [{"section": "a11y", "level": "warn", "key": "a11y/touch", "msg": "…"}],
  "regression": {"broke": [], "fixed": ["dom/tFinal"]},
  "timings": [{"id": "screens", "title": "…", "seconds": 4.1}],
  "exit": 0 }
```

هر نتیجه یک `key`ِ پایدار دارد (مثلِ `screens/داشبورد`) که بینِ اجراها عوض نمی‌شود —
مقایسه‌ی رگرسیون روی همین کلیدها انجام می‌شود.

## تستِ خودِ بازرس

    python3 tests/run.py              # همه (حدودِ یک دقیقه)
    python3 tests/run.py a11y forms   # فقط چند تست

برای **هر بررسی** دو نمونه در `tests/fixtures/` هست: یکی که عمداً همان باگ را دارد
(بازرس باید بگیرد) و یکی سالم (بازرس نباید قرمز بدهد). تستِ خطای مثبتِ کاذب به‌اندازه‌ی
تستِ گرفتنِ باگ مهم است — مثلاً مقایسه‌ی تصویری هم روی صفحه‌ی بی‌تغییر آزموده می‌شود،
هم روی صفحه‌ای با ساعتِ زنده (که باید ماسک شود)، هم بدونِ ماسک (که باید گزارش شود،
وگرنه آزمونِ ماسک بی‌معنی است).

بدونِ سبز شدنِ `tests/run.py` تغییری را قبول نکن.

## قانون‌ها

* **موتور عمومی است.** هیچ نامِ تابع، شناسه، جدول یا رشته‌ی مخصوصِ یک پروژه داخلِ `audit.py` نیست؛
  هرچه مخصوصِ پروژه است در `audit.config.json`.
* **تنظیمات بینِ پروژه‌ها نشت نمی‌کند.** تنظیمات/شِما/شبیه‌ساز فقط از کنارِ خودِ پروژه
  یا مسیرِ صریح خوانده می‌شود.
* `bad()` یعنی تحویل نده، `warn()` یعنی نگاه کن. هرچه مطمئن نیستیم `warn` است.
* در حالتِ خودکار (وقتی `screens` در تنظیمات نیست) موتور نامِ توابع را از `onclick` حدس می‌زند
  و کورکورانه صدا می‌زند؛ در آن حالت خطاها **هشدار**اند نه ایراد. این رفتار عمدی است.

## درس‌هایی که این بازرس از آن‌ها ساخته شد

* تستی که تابع را مستقیم صدا می‌زند، باگِ چیدمان و پوششِ لمس را هرگز نمی‌گیرد.
* فقط یک تم تست کردن، رنگ‌های ثابتِ جامانده را پنهان می‌کند.
* `innerText` متنِ بخش‌های مخفی را نمی‌دهد؛ نشتِ `NaN` با `textContent` روی برگ‌های DOM پیدا می‌شود.
* تا وقتی عکسِ صفحه را با چشم نبینی، مطمئن نیستی.
* هشدارِ الکی از هشدار ندادن بدتر است؛ بررسی‌ای که اشتباه می‌گیرد را حذف کن یا دقیقش کن.
* شناسه‌ی پویا (`getElementById('q'+i)`) شناسه‌ی گمشده نیست — بررسی باید فقط شناسه‌ی ثابت را ببیند.
* کتابخانه‌ای که بار می‌شود ولی کارش را نمی‌کنی، حدودِ نیمی از بایت‌هایش هنگامِ تعریفِ خودش
  اجرا می‌شود؛ پس معیارِ «بلااستفاده» باید بایتِ هدررفته باشد، نه فقط نسبتِ پوشش.
* یک بررسیِ کنتراست نوشتیم و دور انداختیم: با مقایسه‌ی رنگِ CSS، دکمه‌های گرادیانی را اشتباه
  «نامرئی» گزارش می‌کرد. اگر دوباره سراغش رفتی، حتماً پیکسل‌محور باشد.
